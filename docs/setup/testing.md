# Testing what you build

Three tiers, and yours gets the middle one for free.

## Without a window

`Probe` opens your compiled blueprints and drives them — click a button, type into a
field, assert the signal moved — with no device and no font. This is the layer worth
having, because a screenshot cannot tell you that a button wrote the right signal, and a
person should not have to.

Nothing in it is a mock. It runs against the same `.rdab` the application ships, with the
real compiled bindings and the signals `state.ts` declared. If this passes and the
application is broken, the bug is in the drawing.

For [the first interface](first-interface/README.md), `tests/LayoutTests.cpp`:

```cpp
#include <Layout/Probe.h>
#include <RdaState.h>            // generated by rda_add_state

#include <cstdio>

int main() {
    using namespace RDA;
    using namespace RDA::Layout;

    // The names first, for the same reason the application does it first.
    State::define();
    int saved = 0;
    State::onSave([&] { ++saved; });

    Probe probe;
    if (!probe.open("res/layouts/home.rdab")) {
        std::printf("could not open the blueprint: %s\n", probe.error().c_str());
        return 1;
    }

    int failures = 0;
    auto check = [&](bool ok, const char* what) {
        std::printf("  %s  %s\n", ok ? "ok  " : "FAIL", what);
        if (!ok) ++failures;
    };

    State::setCount(0);
    probe.settle();
    check(probe.text("root/title") == "Clicked 0 times", "the title reads the count");

    check(probe.click("root/buttons/add"),         "the add button exists");
    check(State::count() == 1,                     "and clicking it moved the signal");
    probe.settle();
    check(probe.text("root/title") == "Clicked 1 time", "and the title followed, singular");

    check(probe.click("root/buttons/reset") && State::count() == 0, "reset returns to zero");

    check(probe.type("root/notes", "hello"),       "typing into the field");
    check(State::notes() == "hello",               "reaches the signal");

    check(probe.click("root/save") && saved == 1,  "save asked the backend, once");

    return failures ? 1 : 0;
}
```

The ids are the paths the compiler assigned from the `id` on each element —
`rda dump res/layouts/home.rdab` prints them. Renaming a widget breaks these tests, which
is the point: a test that kept passing through a rename was not testing that widget.

`settle()` evaluates whatever bindings a write made dirty, which the running application
does once a frame. Read a bound `text` after a write without it and you read the old
value.

Register it beside the application:

```cmake
add_executable(myapp_tests tests/LayoutTests.cpp)
target_link_libraries(myapp_tests PRIVATE rendeer)
# RdaState.h is generated here by rda_add_state(myapp ...)
target_include_directories(myapp_tests PRIVATE "${CMAKE_BINARY_DIR}/generated/myapp")
add_dependencies(myapp_tests myapp)   # the blueprints are compiled by the app's build

enable_testing()
add_test(NAME myapp_tests COMMAND myapp_tests
         WORKING_DIRECTORY "${CMAKE_BINARY_DIR}/bin/$<CONFIG>")
```

`WORKING_DIRECTORY` because the blueprint is opened relative to it, exactly as the
application opens it. Then `ctest --test-dir build -C Debug`.

What `Probe` can do: `click(id)`, `set(id, bool)` for a checkbox, `set(id, double)` for a
slider, `type(id, text)`, `choose(id, value)` for a `<select>`, `showTab(id, index)`, and
read back `text(id)`, `shown(id)`, `exists(id)` and `ids()`. Everything a layout can do
without a pointer.

## With one

A layout that compiles is not a layout that works. Give the application a `--frames N`
argument that stops it after N frames, and it can be run and checked without a person:

```cpp
int main(int argc, char** argv) {
    int frames = (argc == 3 && std::string(argv[1]) == "--frames") ? std::atoi(argv[2]) : 0;
    // ...
    config.onUpdate = [&](float) {
        gHost.reloadIfChanged();
        if (frames > 0 && --frames == 0) rendeerStop();
    };
    // ...
}
```

Then a smoke script builds everything — which compiles every `.tsx`, the theme and the
state — runs the tests above, and runs each screen for sixty frames, failing if the exit
code is not zero **or the log holds anything worse than INFO**:

```bash
./myapp --frames 60 && ! grep -E '^\[(ERROR|WARNING)\]' RDA_DEBUG.txt
```

That second half is the one that catches things. A run can exit cleanly and still have
warned that a binding found no signal, or that a command was asked for which nothing had
declared.

## And the engine's own

Which you inherit. `scripts/test.bat` in the checkout covers the expression VM, the
layout rules, the animation arithmetic, and all three language bindings. If you are
writing a binding for a fourth language, [`bindings/tests/`](../../bindings/tests/README.md)
is the checklist to copy — the same questions, asked in the same order, in each.
