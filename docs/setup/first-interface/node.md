# Your first interface, in Node

The three files under `res/` are on [the previous page](README.md); the `package.json`
is [a Node project](../adding-to-a-project/node.md). This is the one file left.

## `app.mjs`

```js
import * as rda from 'rda'
import { State, Commands, define } from './state.mjs'   // generated by `npx rda build .`

// init() returns once the engine is up, so there is no callback to nest this in.
rda.init({ name: 'My application', theme: 'res/themes/app.rdth' })
define()
rda.loadInterface('res/layouts/home.rdab', 'res/layouts/home.tsx')

Commands.save(() => console.log('saving:', State.notes))

await rda.run()
```

`state.mjs` was generated from `res/state.ts`. `State` is a real object of accessors,
made non-extensible, so `State.notAThing = 1` throws where it is written and your editor
completes the names that exist.

The second argument to `loadInterface` is the layout's source. A Debug engine watches it
and recompiles the blueprint when you save, which is what rebuilds the screen in place.

`run()` is what keeps the process alive. It polls for commands on a timer and resolves
when the window closes; everything else Node is doing carries on between its ticks. A
handler here is not inside a frame, so it may `await` — an HTTP request answered as a row
in a list is an ordinary thing to write. [The Node backend](../../backend/node.md) explains
why a command is collected rather than called.

## Run it

```bash
npm install                                      # once: links rda from the checkout
npx rda build .
node app.mjs
```

From the project directory. `npm install` links `node_modules/rda` into the engine
checkout, koffi and all; `rda build` compiles the theme and the layout beside their
sources and writes `state.mjs`; `node app.mjs` opens the window, with the engine loaded
from the checkout's `bin/`.

Press *Save* and the console prints whatever is in the field.
