# Your first interface, in C#

The three files under `res/` are on [the previous page](README.md); the `.csproj` is
[a C# project](../adding-to-a-project/csharp.md). This is the one file left.

## `Program.cs`

```csharp
using Rendeer;
using RdaState;              // generated by `rda build . --csharp`, from the .csproj

Rda.Init(new StartupConfig { Name = "My application", Theme = "res/themes/app.rdth" });
Schema.Define();
Rda.LoadInterface("res/layouts/home.rdab", "res/layouts/home.tsx");

Commands.save(() => Console.WriteLine($"saving: {State.notes}"));

Rda.Wait();
```

`state.cs` was generated from `res/state.ts`, and this is the binding where the
declaration's guarantee is strongest: `State.notAThing` is not a member, so the line
does not compile. A table's row is a generated struct, so a misspelled column or a wrong
type is a build error too.

The names are the declaration's — `State.count`, not `State.Count`. Unusual for C#, and
deliberate: `state.count` in a layout, `State::count()` in C++ and `State.count` here are
one signal, and a generator that renamed things would make every reader translate.

The second argument to `LoadInterface` is the layout's source; a Debug engine watches it
and rebuilds the screen when you save.

`Init()` returns with the engine running on its own thread, so set-up is flat top-level
code. A command handler is an ordinary delegate, invoked on the engine's loop thread
inside the frame the interface asked in — so keep it quick, and do not block in it.

## Run it

```bash
dotnet run
```

From the project directory. The build runs the tool over `res/` first, which is where
`state.cs` comes from, then compiles this and starts it. The engine's DLL and its font
were copied beside the executable by the `.csproj`.

Press *Save* and the console prints whatever is in the field.
