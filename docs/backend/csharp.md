# C#

`bindings/csharp/`, P/Invoke over the C ABI. Nothing to install: the binding is two source
files and the engine is a shared library.

```csharp
using Rendeer;
using RdaState;              // generated by `rda csharp`

Rda.Init(new StartupConfig { Name = "My application", Theme = "res/themes/app.rdth" });
Schema.Define();
Rda.OpenRoutes(Routes.All, "res/layouts");

Commands.save(() => Console.WriteLine(State.title));

Rda.Wait();
```

## The compiler checks more of it than anywhere else

This is the binding where the declaration's guarantee is strongest. Python and Node catch
a misspelling when the line runs; C# does not let it exist:

```csharp
Tables.products.Fill(new[] {
    new Tables.products.Row { title = "Widget", price = 9.0, inStock = true },
});

State.notAThing = 1;     // not a member -- this does not compile
```

A row is a generated struct rather than a mapping, so a wrong column name is a build
error, and so is a wrong *type* in a column.

## The names are the declaration's

`State.count`, not `State.Count`. Unusual for C#, and deliberate: `state.count` in a
layout, `State::count()` in C++, `State.count` in Python and `State.count` here are one
signal. A generator that renamed things would make every reader translate. A declared name
that collides with a keyword becomes a verbatim identifier — `@class` — rather than being
renamed for the same reason.

## Two things P/Invoke gets wrong by default

**Strings are UTF-8 on this ABI, and a bare `string` parameter is not.** The default
marshalling is ANSI; written that way and read back, `"éàü — café"` returns as U+FFFD
replacement characters. The text is destroyed on the way in, silently, and only for the
inputs an English test never uses. Every string going out carries
`[MarshalAs(UnmanagedType.LPUTF8Str)]`, every string coming back is read as `byte[]` and
decoded. Measured both ways.

**A delegate handed to native code must outlive the call that registered it** — the trap
every language with callbacks has, and the reason the Python binding keeps its trampolines
in a module-level list.

`CallingConvention.Cdecl` is declared explicitly as well. On x64 there is only one
convention and it makes no difference; on x86 the default is StdCall and this ABI is not,
which is a stack corruption rather than an error message.

## Commands are real callbacks

Unlike Node, and this was measured rather than assumed: the CLR takes a call from a
foreign thread, and the engine reaches a C# delegate **on its own loop thread**. So a
handler is an ordinary delegate invoked inside the frame the interface asked in — which
means it should be quick, and must not block on anything the loop is responsible for.

## Threading

`Init()` returns once the engine is up, so set-up is flat top-level code. Every call is
synchronous and costs a round trip to the next frame, exactly as in the other two.
