## Skipping the typing

This page writes the files out so you can see what each is for. To get a smaller version of them on disk, run `rda init myapp --python` (or `--node`, `--csharp`, `--cpp`, or no flag for the interface alone) and then `rda prototype .` inside the folder. The project it makes is a counter and a command, in a layout called `main.tsx`; everything below applies to it unchanged, and it is a better start than a blank file once you have read how the pieces fit.

## res/state.ts — what both sides agree on

```ts title="res/state.ts"
export const state = {
  count: { value: 0,  doc: "how many times the button has been pressed" },
  notes: { value: "", doc: "what is typed in the field" },
}

export const commands = {
  save: "write the notes somewhere",
}
```

Declared once, here. The build generates every other side from it: the C++ header, the Python module, the JavaScript module, the C# class, and the TypeScript the layout is checked against. So `state.count` in the layout and `State::count()` in C++ — or `State.count` anywhere else — are the same signal **by construction**, and a misspelling on either side is a compile error rather than a value that quietly holds zero forever.

A field’s type is whatever its initial value is. The long form `{ value, doc }` is optional, and the documentation reaches every generated side and the tooltip your editor shows.

## res/themes/app.ts — the look

```ts title="res/themes/app.ts"
export const button: RdaButtonTheme = {
  default: { transitionMs: 140, easing: "out" },
  primary: {
    normal: "#3A6AD0", hovered: "#4C7CE6", pressed: "#2A54B4",
    text: "#FFFFFF", radius: 6,
  },
}

export const label: RdaLabelTheme = {
  heading: { color: "#DDE3EC", fontSize: 22, weight: "bold" },
}

export const textfield: RdaTextfieldTheme = {
  default: { transitionMs: 140, easing: "out" },
  notes: {
    mode: "document", background: "#1C1E24", text: "#DDE1E8",
    border: "#333A46", borderWidth: 1, radius: 8, padding: 14,
  },
}
```

Each export names a widget type; each key inside it is a variant, chosen by a widget with `variant="..."`. A field left out inherits from that widget’s `default`, so every entry is only the decisions it makes. `transitionMs` on `default` is why a button’s colour follows the pointer instead of snapping.

The `: Rda...Theme` annotations come from the generated `rda.d.ts`, so a misspelled field is a red squiggle before it is a build error.

## res/layouts/home.tsx — the interface

```tsx title="res/layouts/home.tsx"
export default function Home() {
  return (
    <stack id="root" arrange="vertical" spacing={8} padding={12} animate={160}>
      <label id="title" variant="heading" height="content"
             text={() => `Clicked ${state.count} ${state.count === 1 ? "time" : "times"}`} />

      <stack id="buttons" arrange="horizontal" spacing={6} height="content">
        <button id="add"   variant="primary" text="Add one" width={110} height="content"
                onClick={() => state.count++} />
        <button id="reset" text="Reset" width={110} height="content"
                onClick={() => state.count = 0} />
      </stack>

      <textfield id="notes" mode="document" variant="notes" height="fill"
                 text={() => state.notes}
                 onChange={(typed) => state.notes = typed} />

      <button id="save" text="Save" width={110} height="content"
              onClick={() => commands.save()} />
    </stack>
  )
}
```

Three kinds of value, and this file has all of them. `text="Reset"` is a **constant**, written into the blueprint. `text={() => ...}` is a **binding**, parsed at build time into stack operations over `state` and evaluated when a signal it reads changes, at no other time. `onClick={() => ...}` is a **handler** — the same machinery pointed the other way.

`commands.save()` names work for the backend to do. The layout says *which*; the backend says *what*.

## res/layouts/tsconfig.json — for the editor only

```json title="res/layouts/tsconfig.json"
{
  "compilerOptions": {
    "noEmit": true, "strict": true, "target": "ES2020", "module": "ESNext",
    "moduleResolution": "bundler", "jsx": "react", "jsxFactory": "h",
    "types": [], "skipLibCheck": true
  },
  "include": ["rda.d.ts", "*.tsx", "../themes/*.ts", "../state.ts"]
}
```

Nothing emits from it, and it is worth more than it looks. `<div>` and `colour="#fff"` both produce a blueprint, with a warning from the build (`<div> ... is not an element; did you mean <container>?`) — and the loader then skips the element and ignores the property, so `rda build --strict` makes the warning an error. This file plus the generated `rda.d.ts` is what catches that typo while you are still typing it, and `rda widgets` lists what each element accepts.

## The backend

One more file, in whichever language you are writing. Python, in full:

```python title="app.py"
import rda
from state import State, Commands, define    # generated by `python -m rda build .`

config = rda.StartupConfig()
config.name = "My application"
config.theme = "res/themes/app.rdth"

@Commands.save
def on_save():
    print("saving:", State.notes)

@config.on_start
def opened():
    define()                                  # the names, before the layout
    rda.load_interface("res/layouts/home.rdab", "res/layouts/home.tsx")

rda.init(config)
rda.wait()
```

Every signal on `State` is a real property with the type and documentation the declaration gave it, so `State.notAThing = 1` is an `AttributeError` where it is written. `@Commands.save` at module level runs at import — before the engine exists and before the declaration has created the command — and the binding remembers it and applies it once `on_start` has declared the names.

The second argument to `load_interface` is the layout’s source. A Debug engine watches it and recompiles the blueprint when you save. `init()` returns with the engine running on its own thread, so the interpreter stays yours; `wait()` is for when there is nothing left to do but let it live.

## Run it

```bash
python -m rda build .
python app.py
```

A heading reading *Clicked 0 times*, two buttons, a text area, and a Save button. *Add one* counts; *Reset* returns to zero; *Save* prints whatever is in the field, from the backend.

Then, with the application still running, change `"Add one"` to `"Add"` in `home.tsx` and save the file. The interface rebuilds in place and **the count survives** — state lives in the application, not inside the thing being replaced. The theme reloads the same way, so a colour can be changed and looked at without restarting anything.

> To see an interface before any backend exists, run `rda prototype .` in the project. It opens the same window with every signal at its declared value, and every command prints a line to the terminal.
