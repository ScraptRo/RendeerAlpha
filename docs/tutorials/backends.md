## The declaration is the source of truth

```ts title="res/state.ts"
export const state = {
  count:  { value: 0,  doc: "how many times the button has been pressed" },
  title:  { value: "", doc: "what the window is showing" },
  ready:  false,
}

export const commands = {
  save: "write the notes out",
}

export const tables = {
  products: {
    title:   { value: "", doc: "what it is called" },
    price:   { value: 0,  doc: "in whole currency units" },
    inStock: false,
  },
}

export const routes = {
  home:      { layout: "home" },
  catalogue: { layout: "catalogue", params: ["productId"] },
}
```

| the build runs | and generates |
| --- | --- |
| `rda state  decl.ts out.h` | `RdaState.h` — the C++ |
| `rda python decl.ts out.py` | `state.py` — the Python |
| `rda node   decl.ts out.mjs` | `state.mjs` — the JavaScript |
| `rda csharp decl.ts out.cs` | `state.cs` — the C# |
| `rda types  out.d.ts theme.ts decl.ts` | `rda.d.ts` — what a layout is checked against |

So `state.count` in a layout, `State::count()` in C++ and `State.count` in Python, Node or C# are the same signal by construction. Declaring `routes` adds two things for free: a `route` signal holding the name of the screen showing, and `back` / `forward` as commands.

## C++

```cpp title="main.cpp"
#include <RendeerAlpha.h>
#include <Layout/LayoutHost.h>
#include <RdaState.h>            // generated by rda_add_state

namespace { RDA::Layout::LayoutHost gHost; }

int main() {
    RDA::AppConfig config;
    config.app.name      = "My application";
    config.gui.themePath = "res/themes/app.rdth";

    config.onStart = [] {
        // The names first: a binding resolves what it reads when it is created.
        RDA::State::define();

        RDA::State::onSave([] {
            std::cout << "saving: " << RDA::State::notes() << "\n";
        });

        gHost.open(getMainWindow()->gui().retained(),
                   "res/layouts/home.rdab", "res/layouts/home.tsx");
    };

    // Reloading restructures the widget tree, so it happens here rather than
    // inside a widget callback — a callback fires while that tree is walked.
    config.onUpdate = [](float) { gHost.reloadIfChanged(); };

    rendeerRun(config);
}
```

Everything typed comes from `RdaState.h`: `RDA::State::count()`, `setCount()`, `notes()`, `onSave()`. Rename `save` in the declaration and this file stops compiling, which is the point. `rendeerRun` blocks until the window closes — the engine owns the window and the loop, and the callbacks are your program.

## Python, Node and C#

The same four jobs through the C ABI. Python is ctypes, Node is koffi, C# is P/Invoke — and in every case the engine is a shared library the backend opens, not the other way round.

```javascript title="app.mjs"
import * as rda from 'rda'
import { State, Commands, define } from './state.mjs'   // generated by `rda node`

rda.init({ theme: 'res/themes/app.rdth' })
define()
rda.loadInterface('res/layouts/home.rdab')

Commands.save(() => console.log(State.notes))

await rda.run()
```

```csharp title="Program.cs"
using Rendeer;
using RdaState;              // generated by `rda csharp`

Rda.Init(new StartupConfig { Theme = "res/themes/app.rdth" });
Schema.Define();
Rda.LoadInterface("res/layouts/home.rdab");

Commands.save(() => Console.WriteLine(State.notes));

Rda.Wait();
```

Same layouts, same theme, same router, same animation. In Node, `init()` returning means a server and a window are one program; in Python it means the REPL, the web server or the data pipeline carries on while the window is open. In C#, the generated state makes a misspelled signal a build error.

## Drawing, in the one place a backend draws

A `<viewport>` is a hole the application fills, because inside one there is nothing for the interface to decide. C++ gets the Vulkan command buffer there — inside the render pass, with the device, the allocator and the render pass to build against. Every other language gets a list of 2D commands: rectangles, lines and text in the viewport’s own coordinates, drawn with the same rasteriser the widgets use, so a colour there is the same pixels as that colour in a theme.

> One offscreen target exists, so one viewport at a time can be the Vulkan one. Any number can be 2D.

## Any language with an FFI

The interface layer is reached through a C ABI, so a backend can be written in anything that can call into a shared library. Python, Node and C# each took the same six steps, and the C ABI documents the threading contract, the error surface and what a binding has to provide. Four languages having driven the seam is a different thing from one language having designed it.
